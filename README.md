# NetworkSim — модель работы вычислительной сети при выполнении задачи

Лабораторная работа по объектно-ориентированному программированию, вариант 12:
«Модель работы вычислительной системы или сети при выполнении некоторой задачи».

Приложение моделирует выполнение задач в сети из двух сегментов. Задача — пакет,
который движется по дорожкам сети и последовательно проходит цепочку узлов:

**Коммутатор → Брандмауэр → Сервер приложений → База данных**

Возможные проблемы и реакция на них:

| Проблема | Где возникает | Кто устраняет | Что происходит |
|---|---|---|---|
| Ошибка данных | Брандмауэр, Сервер приложений | Клиент | Пакет-ошибка возвращается клиенту, он исправляет её и отправляет задачу заново с начала цепочки |
| Отказ узла | База данных | Администратор | Администратор «подключается по SSH», ремонтирует узел; обработка продолжается с места отказа |

Готовый результат возвращается **клиенту**; пользователь стоит рядом с клиентом
и радуется, когда клиент передаёт ему результат (пунктирная стрелка на схеме).

## Запуск

**Visual Studio 2022:** открыть `NetworkSim.sln` и нажать F5 (проект — Windows Forms,
C#, .NET 8; нужен набор «Разработка классических приложений .NET»).

**Командная строка:** `dotnet run --project NetworkSim` из папки решения.

## Управление

- **Старт / Стоп** — запуск и остановка модельного времени.
- **Задача** — отправка одной задачи по команде пользователя.
- **Сброс** — полная пересборка модели в исходное состояние.
- **Скрыть журнал / Показать журнал** — освобождает место для сцены.
- **Вероятность ошибки данных** — сбой типа «ошибка данных» на брандмауэре и сервере приложений.
- **Вероятность отказа БД** — сбой типа «отказ узла» на базе данных.
- **Время обработки** — время обработки одного пакета каждым узлом, с.
- **Скорость** — коэффициент ускорения модельного времени (0,5×–4×).
- **Автоотправка задач** — клиент отправляет задачи автоматически каждые 6 с.

В журнале внизу отображаются все события модели с отметкой модельного времени;
в строке состояния — счётчики (отправлено, доставлено, возвращено ошибок, ремонтов,
задач в полёте). Одновременно в работе может находиться не более 5 задач.

Под узлом видна **очередь пакетов**: они нарисованы кружками в лотке и обрабатываются
по очереди. Счётчики сбоев узлов выводятся в журнал (например, «всего блокировок: 3»).

## Структура проекта

```
NetworkSim/
  Program.cs                  — точка входа
  MainForm.cs / .Designer.cs  — главное окно (настройки, сцена, журнал)
  Model/                      — модель (не зависит от интерфейса)
    Enums.cs                  — перечисления состояний и типов
    EventArgsTypes.cs         — аргументы событий
    IPacketEndpoint.cs        — интерфейс «принимает пакеты»
    IDrawable.cs              — интерфейс «умеет рисовать себя»
    SimulationClock.cs        — часы модельного времени (единственный источник времени)
    TrackGraph.cs             — граф дорожек сегмента и поиск маршрута (BFS)
    Packet.cs                 — пакет, движущийся по дорожкам
    ProcessingNode.cs         — ОСНОВНОЙ класс: узел обработки (базовый)
    FirewallNode.cs           — наследник: брандмауэр
    AppServerNode.cs          — наследник: сервер приложений
    DatabaseNode.cs           — наследник: база данных
    NetworkSegment.cs         — базовый сегмент сети («окружающая среда»)
    ClientSegment.cs          — клиентский сегмент (наследник)
    ServerSegment.cs          — серверный сегмент (наследник)
    Client.cs                 — клиент (отправляет задачи, исправляет ошибки, принимает результат)
    Administrator.cs          — администратор (ремонтирует отказавшие узлы)
    EndUser.cs                — получатель результата (реагирует на переданный результат)
    SimulationLogger.cs       — журнал событий (наблюдатель)
    SimulationWorld.cs        — сборщик модели, счётчики, отправка задач
    Layout.cs                 — координаты всех объектов сцены
  View/
    SimulationCanvas.cs       — панель отрисовки сцены (GDI+, двойная буферизация)
```

## Демонстрационные сценарии

1. **Успех** (вероятности 0,0): «Старт» → «Задача» — пакет проходит все узлы,
   результат возвращается клиенту, клиент передаёт его пользователю.
2. **Ошибка данных** (вероятность ошибки 0,3): красный треугольник возвращается
   клиенту, клиент исправляет ошибку, задача идёт заново с попыткой 2
   (номер попытки виден на пакете).
3. **Отказ узла** (вероятность отказа 0,2): база данных краснеет с крестом,
   задачи копятся в очереди, администратор подключается по SSH, зелёная команда
   ремонта едет к узлу, обработка продолжается без повторного прохода цепочки.
